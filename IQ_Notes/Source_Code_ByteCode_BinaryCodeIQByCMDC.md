# Source Code vs Byte Code vs Binary/Machine Code

## The Pipeline

```
Source Code (.js)  →  Byte Code (V8 Ignition)  →  Machine Code (V8 TurboFan)
  (human readable)      (intermediate IR)          (CPU instructions)
```

---

## Table Comparison

| Aspect | Source Code | Byte Code | Binary / Machine Code |
|--------|-------------|-----------|----------------------|
| **Example** | `console.log("Hello JS!");` | `LdaSmi #1` `Star r0` `CallRuntime [ConsoleLog, r0]` | `48 8b 45 f8 89 04 24 e8 ...` |
| **Readable by humans?** | ✅ Yes — plain text, uses keywords & symbols | ⚠️ Partially — mnemonic opcodes, but lower-level | ❌ No — raw bytes / hex |
| **Needs translation?** | No — written directly by developer | Yes — compiled FROM source code | Yes — compiled/assembled FROM byte code |
| **Execution** | Interpreted by JS engine (V8, SpiderMonkey) | Interpreted by V8's Ignition interpreter | Executed directly by the CPU |
| **Speed** | Slowest (parsing + interpretation overhead) | Faster than source (already tokenized & structured) | Fastest — native CPU execution |
| **Portability** | Cross-platform (runs anywhere with a JS engine) | Cross-platform (V8's bytecode is engine-specific though) | Platform-specific (x86, ARM, etc.) |
| **Optimization** | No optimization | Light optimizations during bytecode generation | Heavy optimizations (TurboFan JIT) |
| **Generated by** | You (the developer) | V8's **Ignition** interpreter (first step) | V8's **TurboFan** compiler (hot code) |

## Applied to `01_HelloWorld.js`

```javascript
console.log("Hello JS!");
```

### What happens when V8 runs this:

```
Step 1: Parser
─────────────────────────────────────────────────────
  console . log ( "Hello JS!" )
  ↓
  Produces an AST (Abstract Syntax Tree)

Step 2: Ignition (Bytecode Generator)
─────────────────────────────────────────────────────
  AST → Byte Code (~4-5 instructions, engine-specific)

  Pseudocode bytecode:
    LdaGlobal  "console"         // Load console object
    Star       r0                 // Store in register r0
    LdaSmi     "Hello JS!"       // Load the string literal
    Star       r1                 // Store in register r1
    CallProperty r0, "log", r1   // Call console.log(r1)

Step 3: TurboFan (JIT Compiler) — for hot/frequent code
─────────────────────────────────────────────────────
  Byte Code → Optimized Machine Code (x86-64 example)

  mov     rdi, [console_obj]
  lea     rsi, [string_"Hello JS!"]
  call    ConsoleLog
```

## Real Byte Code (V8 Ignition)

If you want to *actually see* what byte code V8 generates for this file, you can run:

```bash
node --print-bytecode 01_HelloWorld.js
```

This dumps the real Ignition bytecode — a list of one-byte opcodes (e.g., `0x12 LdaGlobal`, `0x1b Star`) that V8's interpreter steps through.

---

## Key Takeaway

- **You write** source code (human-friendly).
- **The engine compiles** it to byte code (a compact, low-level intermediate representation).
- **Hot code** gets JIT-compiled to machine code (raw CPU instructions).
- You only ever interact with **source code**. Byte code & machine code are the engine's internal business.
